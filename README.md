# Звіт до роботи
## Тема: Написання тестів на пайтон
### Мета роботи: Навчитися писатитести на пайтон

---
### Виконання роботи

*У ході виконання завдання було реалізовано перевірку даних за допомогою `assert` та `raise`, створено класи з валідацією вхідних параметрів. Проведено юніт-тестування за допомогою бібліотек `unittest` та `pytest`, протестовано функціонал класів і обробку помилок. Використано `coverage` для аналізу покриття коду тестами, згенеровано html-звіт для візуалізації. Також було протестовано запуск тестів з терміналу та через VS Code. Усі завдання виконано в повному обсязі. Всі результати виконаної роботи та приклади коду будуть у [файлі]().

---
### Висновок:

*Що зроблено в роботі:

- Ознайомлено з базовими та розширеними методами тестування Python-програм.
- Реалізовано валідацію даних за допомогою `assert` та конструкції `raise`.
- Створено класи з перевіркою коректності введених аргументів.
- Проведено тестування за допомогою `unittest` з використанням декількох `assertEqual` та `assertRaises`.
- Написано тести з використанням бібліотеки `pytest`.
- Проведено аналіз покриття коду тестами за допомогою `coverage` / `pytest-cov`.
- Згенеровано html-звіт покриття для перегляду у браузері.

* Чи досягнуто мети роботи:
Так, всі цілі лабораторної роботи досягнуто — вивчено і застосовано основні техніки тестування в Python.

*Які нові знання отримано:
- Як використовувати `assert` для валідації у коді.
- Створення та запуск юніт тестів з `unittest` та `pytest`.
- Основи роботи з покриттям тестами (`code coverage`) і як його виміряти.
- Розуміння важливості модульного тестування для підтримки якості коду.

*Чи вдалось відповісти на всі питання задані в ході роботи:
 Так, на всі питання було надано відповіді в процесі виконання завдання.

*Чи вдалося виконати всі завдання:
Так, всі обов’язкові та додаткові завдання були виконані.

*Чи виникли складності у виконанні завдання:
Невеликі труднощі виникли під час налаштування `pytest` та встановлення залежностей у середовищі `poetry`, однак після ознайомлення з документацією — все вирішилось.

*Чи подобається такий формат здачі роботи (Feedback):
 Так, формат роботи дуже зручний: поєднання теорії, практики, коду та тестів робить процес навчання зрозумілим і ефективним.

*Побажання для покращення (Suggestions):
Було б зручно мати шаблон проекту з базовою структурою (наприклад, `app.py`, `test.py`, `pyproject.toml`) для швидшого старту роботи. Також було б цікаво доповнити завдання розділом з автоматичним CI (наприклад, GitHub Actions).
